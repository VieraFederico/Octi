# Decisions

Log of design decisions. Every decision is made by the student; Claude proposes options.

| ID | Decision | Alternatives considered | Why |
|---|---|---|---|
| D-001 | Env var names follow the assignment (§3.2–3.3): `LITELLM_BASE_URL`, `LITELLM_API_KEY`, `LLM_MODEL`, `EMBEDDING_MODEL`, `LANGSMITH_*`, `PINECONE_*` | `LLM_SERVICE_URL` / `LLM_API_KEY` | Match the names the assignment specifies |
| D-002 | LangSmith project `octi`; Pinecone index `octi-tables` | Assignment's example names `mas-2026s2-<legajo>` / `mas-2026s2-tables` | Project name; assignment presents names as example config, not a requirement. Pinecone requires lowercase |
| D-003 | Embedding model `text-embedding-3-small` (1536 dims); Pinecone index dimension 1536 | `text-embedding-3-large` (3072 dims) | Inputs are short table-metadata texts and the corpus is small; cheaper and faster, enough quality. Changing it later requires re-creating the index and re-ingesting |
| D-004 | Two-level decision logs: project-wide decisions in root `DECISIONS.md` (`D-NNN`); spec-local decisions in `specs/NN-name-plan-artifacts/DECISIONS.md` (`SNN-D-NNN`), following the `write-spec-plan` artifact contract; decisions made during `/write-spec` also folded into the spec text | Single root log for everything; per-spec logs with unprefixed `D-NNN` | Matches the SDD skill and the course labs; keeps each spec self-contained; the `SNN-` prefix makes IDs unambiguous across specs (e.g. in the oral exam) |
| D-005 | Spec roadmap: 00 foundation; 01 Ingestion agent (+ table store, upload/explore UI); 02 Analyst agent (+ sandbox, ask UI, answerability); 03 evaluation + docs + bonus | Table store and sandbox inside spec 00; fewer/more specs | Each decision lives next to the code that needs it; every spec ends with a demo-able slice |
| D-006 | Dependencies in a pinned `requirements.txt`, installed with pip into a student-created `.venv` | `uv` + `pyproject.toml` + lockfile; poetry | Assignment §8 accepts it; same flow as the playground, no new tool on deadline day |
| D-007 | Python `>=3.11`, developed and tested on 3.13 | Pin a single version | Assignment requires 3.11+; the student's environment runs 3.13 |
| D-008 | Folder layout follows the assignment's suggested tree (§9.2.1): `app.py`, `agents/ingestion/`, `agents/analyst/`, `services/`, `data/sample_pdfs/`, `tests/` | `src/octi/` package layout | Recognizable to graders, simpler to explain |
| D-009 | **Superseded by D-013.** Configuration parsed once at the boundary into a typed `pydantic-settings` object ("parse, don't validate"); invalid or missing variables fail fast, naming the fields but never their values | Frozen dataclass over `os.environ` with manual checks | Downstream code receives already-valid, typed values instead of re-checking strings |
| D-010 | The Pinecone index is created by a one-time setup script; the app only checks at startup that it exists with the expected dimension and shows a clear error otherwise | App creates the index lazily on first use | Index creation is setup, not a per-request step; a dimension mismatch is caught before the first upsert |
| D-011 | Tests use pytest, offline by default (LLM, embeddings and Pinecone stubbed); live smoke tests are marked `live` and excluded by default | Live tests in the default run | CLAUDE.md requires offline tests; live checks stay available on demand |
| D-012 | A service-check script verifies LiteLLM chat, embeddings (dimension), Pinecone and LangSmith, printing OK/FAIL per service without secrets; it is part of the README setup instructions | No check; check only inside the app | Proves the setup before building agents; first thing to run when a setup fails |
| D-013 | Configuration: `load_dotenv()` loads `.env` into the environment (so LangChain/LangSmith see it), then a plain Pydantic model parses the needed variables once into a typed `Settings` (secrets as `SecretStr`); failure raises `ConfigError` naming fields, never values. No `pydantic-settings` | `pydantic-settings` (D-009); unparsed `os.environ` reads | `pydantic-settings` does not populate `os.environ`, so LangSmith tracing would silently turn off; plain Pydantic gives typed parsing with no extra dependency |
| D-014 | One Pinecone namespace `octi` (configurable as `PINECONE_NAMESPACE`) holds every Index record | Default namespace; `tables` | Easy full wipe without touching the index; matches the project name |
| D-015 | **Superseded by D-027.** Explicit error hierarchy: `OctiError` → `ConfigError`, `ServiceError(service)` → `LLMServiceError`, `EmbeddingServiceError`, `VectorStoreError`, `TracingError`; later specs add their own. Each carries a user-safe message; the raw cause is chained for logs, never shown in the UI | Catch-all `Exception` handling; raw messages in the UI | Never print keys or raw LiteLLM bodies (CLAUDE.md); failures are named by service |
| D-016 | Chat-first single-page UI: a Chat view (composer with "+" to attach PDFs, ingestion progress inline, questions to the Analyst) and a Library view (indexed tables) behind a `Chat \| Library` toggle; sidebar with logo, "New chat", service status. One conversation per session. The README maps these to the three pages required by §7 | Three classic tabs; multiple conversations per session | Student's product vision (minimal, LLM-app style); still covers upload, explore and ask |
| D-017 | Secret handling: `.env` git-ignored; the service check warns if `.env` is tracked by git; secrets typed `SecretStr` and unwrapped only inside client factories; keys never placed in prompts, graph state or UI messages; `chmod 600` documented as README advice (no effect on WSL `/mnt/c`); generated code reading `.env` is a must-solve item for spec 02's sandbox | Secret managers, encryption at rest, pre-commit scanners | Covers the real leak paths with near-zero code; avoids overengineering |
| D-018 | Logging via stdlib `logging` to stderr, level from `LOG_LEVEL` (default `INFO`), with a redaction filter that replaces any configured secret value with `***` before a line is written | No logging; structured logging stack | Debug output for the developer with a last safety net against leaked keys |
| D-019 | Animated ASCII logo rendered once as HTML with a CSS `@keyframes` animation (frames HTML-escaped), shown only while the conversation is empty | Python loop swapping frames with `time.sleep` | The browser animates; no blocking loop fighting Streamlit's rerun model |
| D-020 | Logo frames read from `assets/logo/frame_*.txt` in filename order at a configurable constant speed (default 8 fps); spec 00 ships 2-3 placeholder frames; empty or missing folder falls back to a plain "Octi" title | Frames embedded in code | Real frames can be dropped in later with no code change |
| D-021 | LLM and embedding client defaults: `temperature=0`, 60 s request timeout, 3 attempts in total by default (`max_retries=2`; attempts = retries + 1, the OpenAI client's built-in exponential backoff with jitter) for transient errors only (timeouts, 429, 5xx); all overridable from `.env`. Wrong answers are retried by the graphs, not here | More retries; no client retries | Rides out proxy hiccups without unbounded loops (assignment §11) |
| D-022 | Agent retry limits (ingestion validation, analyst self-correction) are defined in specs 01/02 next to the loops that use them; spec 00 only makes `Settings` easy to extend | Define them in spec 00 | A setting lives next to its only user |
| D-023 | Spec 00 starts the README: purpose, prerequisites, venv + `pip install`, `.env` setup with security notes, one-time index setup, service check, tests, running the app, where each §7 page lives; later specs append their sections | README written at the end | Reproducible setup from the first spec |
| D-024 | Tracing off (`LANGSMITH_TRACING=false`) is allowed: the app starts with a visible "not traced" sidebar warning and the service check marks LangSmith `FAIL`; tests run with tracing off | Refuse to start when tracing is off | Offline tests need tracing off; an honest untraced banner (course tools lab) keeps normal use compliant with assignment §3.3 |
| D-025 | The app's sidebar status runs only cheap startup checks (configuration, index status, tracing flag) and makes no LiteLLM call; the full service check stays in the script | Run the full service check from the app | Streamlit reruns often; avoids spending proxy budget (§11) and keeps the first screen fast |
| D-026 | Keep the OpenAI client's built-in retries (D-021) instead of the course labs' app-owned ladder (`max_retries=0`, 1-2-4 s); documented in the README | App-owned retry wrapper as in the course labs | Zero code, a single retry layer (no double counting); difference stated openly |
| D-027 | Error hierarchy with group bases and explicit leaves: `AppError` → `ConfigurationError` (→ `InvalidSettingsError`) and `ExternalServiceError` (→ `LLMProxyError`, `VectorStoreError`, `TracingError`, each with leaves such as `ProxyUnreachableError`, `IndexMismatchError`). Octi raises only leaves; leaves carry `user_message` and chain the original cause. New leaves only when code/UI reacts differently or the user message differs. *Amended 2026-10-09 (simplicity audit):* bases are ordinary classes — the runtime `TypeError` guard was removed (it cost more explanation than it protected), and the unused `IndexNotFoundError` was dropped (a missing index is a status) | `OctiError` with directly raisable category classes (D-015) | Every raised error names exactly what happened; `except <Base>` still catches a family; avoids vague raises |
| D-028 | Empty chat: ASCII logo, greeting and inline composer stacked and centered; after the first message the composer is pinned to the bottom (native `st.chat_input` behavior: inline in a container, pinned at top level) | Composer always pinned at the bottom | LLM-app look requested by the student; no custom JS |
| D-029 | Theme: Catppuccin Mocha (base `#1e1e2e`, mantle `#181825`, text `#cdd6f4`), accent Mauve `#cba6f7`, errors Red `#f38ba8`, warnings Yellow `#f9e2af` | Default Streamlit dark; Blue/Peach accents | Student's visual identity; Mauve fits the octopus |
| D-030 | "New chat" with messages opens a confirmation modal (Erase / Cancel / "Don't warn me again"); the opt-out lasts for the browser session only; empty conversation → no modal | Persistent opt-out via cookie/localStorage component | No extra dependency; consistent with one-session state (D-016) |
| D-031 | Invalid configuration and every non-`ok` index status (`missing`, `mismatch`, `unreachable`) show the full Octi error screen instead of the shell; tracing off stays a sidebar warning (D-024) | Shell with sidebar status for index problems | Nothing works without config or the index once spec 01 lands; an honest blocking screen is clearer |
| D-032 | Error screen: animated Octi (frames from `assets/logo/error/`, falling back to main frames) with an ASCII speech bubble (48-char wrap, box characters, tail) saying what failed, what to do and which README section to read; bubble stacks below Octi under 640 px | CSS bubble; same frames as the main logo | Matches the ASCII identity; reuses the D-019/D-020 animation mechanism |
| D-033 | Models: `LLM_MODEL=gpt-5-mini`, `EMBEDDING_MODEL=text-embedding-3-small` (1536 dimensions = the index). Use the short ids, never the `openai/…` aliases: LangChain drops `temperature` only for ids that start with `gpt-5` (those models accept only the default), so with an aliased id `temperature=0` reaches the proxy and fails; with `gpt-5-mini`, `LLM_TEMPERATURE` has no effect | `gpt-5-chat` (fast, honours temperature, weaker at code); `*-pro` (costly, Responses-API only); `gpt-5-nano` (too weak for codegen); Claude ids (less reliable structured output through the OpenAI-compatible proxy); `text-embedding-3-large` (3072 dims, new index, more cost) | Code generation quality matters most (Analyst = 30 %); structured output works; cheap; embedding size matches the existing index |
| D-034 | Project layout follows the assignment (§9.2) and LangGraph's templates: `services/` stays flat, one module per external service holding its client factory and error translation (`llm.py` LiteLLM, `vector_store.py` Pinecone, `tracing.py` LangSmith; later `table_store.py`, `sandbox.py`), plus one shared `services/errors.py`; each agent gets a folder `agents/<name>/` with `graph.py`, `state.py`, `nodes.py`, `prompts.py`, `schemas.py`; tests mirror the source as `tests/unit/test_<module>.py`. A service module becomes a package only when it passes ~300 lines or grows parts used separately. Service modules are not named after their libraries (`pinecone.py`, `langsmith.py`) because that would shadow the library on import | A folder per service with separate client/errors files; errors split per service | Matches the grader's expected layout; Python's "flat is better than nested"; small modules stay readable; the UI catches error families from one module; agents are big enough to split |
| D-035 | Logo art: the student's Octi (40 × 70 characters, Mauve, shown at 0.45 rem). Main logo = 8 frames at 8 fps: mouth closed in frames 1–7 and open in frame 8, so Octi opens his mouth for 1/8 s once per second. Error logo = closed + open alternating, so Octi "talks" next to the speech bubble. The closed frame is derived from the open one by replacing the mouth block. Supersedes the "2–3 placeholder frames" part of D-020 | Closed/open alternating on the main logo (constant talking); static closed logo; per-frame durations in code | Calm logo with a small sign of life; the uneven rhythm comes from repeating a frame, so no new code |
